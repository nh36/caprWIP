## Section guidance

### `Transducer input and output`

- Keep this section short.
- One small table is usually enough.
- The rest of the entry should read as historical-linguistic prose, not
  software documentation.

### `Reconstruction and comparative evidence`

- Give source forms, not vague summaries.
- Name the disagreement directly.
- Explain why the morphological disagreement matters for the expected OE
  inflection.
- If there is no real disagreement, compress the section.

### `Old English evidence`

- Establish attestation and normalization first.
- Say whether the relevant form is a headword, oblique form, variant,
  reconstructed form, or selected comparison form.
- Do not move to paradigm comparison before the OE evidence is clear.

### `Development to Old English`

- Explain the actual path from the chosen input to the OE form.
- Include morphology where it matters, not only sound laws.
- Do not turn this into a recap of packets, DEV_NOTES, or debugging history.

### `Paradigm comparison`

- Use this section when it helps the argument.
- Label manual comparisons honestly.
- Use wording such as `probe output`, `trace output`, `expected`, or `inferred`
  when certainty differs.
- A simple regular entry may omit this section entirely if no cell comparison is
  doing argumentative work.

## Default omissions

- No conclusion section by default.
- Do not add a summary ending unless the entry genuinely needs one.
- Keep regular-with-note entries shorter than complex analogical entries.
