## Reconstruction and early-stage forms

The best reconstructional reading is:

- **cognate-set proto / project headword:** `*sái` (current TSV `PROTO`);
- **OE derivational input:** `*sáiwiz` (current TSV `PROTOFORM`, matching Kroonen's `*saiwi-` / Ringe & Taylor's PGmc `*saiwiz`);
- **intermediate stages in the cited chronology:** `*sāwiz > *sāwi > *sǣi`;
- **OE target:** `sǣ`.

So the crucial distinction is not between two competing OE targets, but between the short cognate-set headword and the fuller i-stem form needed to model OE history. The cited pathway is regular once the correct input and the `w`-loss rule are in place: PGmc `*saiwiz` > PWGmc `*sāwiz` (ai-monophthongization) > NWGmc/pre-OE `*sāwi` (loss of final `-z`) > pre-OE `*sǣi` (`w` loss before fully unstressed `i` plus i-umlaut) > OE `sǣ` (high-vowel apocope).

## Old English philology

The repo evidence supports `sǣ` as the ordinary OE citation form/headword. The intermediate forms `*sāwi` and `*sǣi` are reconstructions only, not attested OE spellings. Kroonen's note, echoed in DEV_NOTES, treats the Germanic source as an i-stem; the packet's lexical-table evidence also matches a straightforward headword `sǣ`, not a special manuscript-only or dialect-only target.

The memo should therefore treat this as an inherited OE lexeme with a regular cited outcome once the correct pre-OE input is chosen. The available repo evidence does **not** justify turning the row into an oblique-cell case, a reconstructed unattested OE target, or a special dialectal entry.

## Project problem and solution

The project problem was historically an implementation problem: older DEV_NOTES say the FST wrongly kept `w` and yielded `*sǣw` from `*saiwiz`. Current packet evidence shows that the cascade now gives `sǣ`, so the sound-law problem itself appears resolved.

What remains project-specific is the column distinction. The row currently represents OE `sǣ` by keeping the set-level proto `*sái` in `PROTO` while feeding the fuller i-stem `*sáiwiz` to the OE derivation in `PROTOFORM`. That is a legitimate project convention, but it is easy for older report/debug text to blur. The final report should describe this as a special **input-history** distinction, not as evidence that OE `sǣ` itself is a late analogical form.

## Paradigm probe

No paradigm probe is required.

This row is not a late-analogy or paradigm-cell-selection case: the target is the citation form `sǣ`, and the current derivation already succeeds directly from the selected input `*sáiwiz`. Neither the packet nor the additional repo search identifies a specific oblique PGmc cell that needs to be tested against the target.

## Recommended final report

Keep the eventual `### Lexeme report` short. It should emphasize that OE `sǣ` is the regular outcome of the fuller i-stem input `*sáiwiz` / `*saiwi-` once `w` loss before unstressed `i` is included, while also making explicit that TSV `PROTO = *sái` is only the cognate-set headword. The stale DEV_NOTES framing (`*sǣw` as current output) should be mentioned, if at all, only as superseded project history.
