### Lexeme report

#### Reconstruction and early-stage alternatives

For `buck`, the project does **not** distinguish `PROTO` from `PROTOFORM`: both remain `*búkkaz`. The row note says explicitly that no lautgesetzlich paradigm-cell rescue is available. Low-vowel cells trigger a-umlaut and high-vowel cells trigger i-umlaut, so the attested form cannot be recovered by simply choosing a different inherited cell.

#### Chronological source dossier

- `Germanic/data/germanic-aligned-final.tsv`: the row is marked as a documented exception and cites Campbell's treatment of `bucca` as an exception to a-umlaut.
- `Germanic/docs/DEV_NOTES.md` groups `*búkkaz`, `*wúlfaz`, and `*wúllō` together as the remaining labial-neighborhood `u`-retention exceptions.
- The row note also frames the problem against the regular a-umlaut environments described in [@Campbell1959] and [@Stiles2012].

#### Old English philology

The target `bucc` is treated as a genuine Old English form. The project is not questioning the lexeme identity or the attestation; it is questioning whether the deterministic inherited sound changes can produce it. The current answer is no.

#### Project problem and solution

This is an `unexplained_unmodelled` case. The FST gives the regular result `bocc`, which matches the comparative expectation better than the attested OE form does. Because no different inherited cell yields `bucc` without creating a different, equally wrong umlaut pattern, the report should describe the exception candidly and not pretend it has been solved.
