## Development-note summary

The live row is an explicit paradigm-cell split rather than a simple lexeme-to-lexeme reflex. `PROTO` `*brándaz` is the cognate-set headword, but the row-level FST input is gen.sg. `*brándas`, and the selected OE target is likewise gen.sg. `brandes`. The packet's compact derivation trace shows that this oblique comparator is regular inside the current cascade: `*brándas -> *brándæs -> brandes`. But the attested/source-backed OE side is stronger for the headword than for the exact row target. Orel lists PGmc `*brandaz I` with OE `brand`, and Clark Hall and Bosworth-Toller both give dictionary headword `brand`, with Bosworth-Toller also preserving ordinary oblique forms such as `brandas`, `branda`, and `brandum` [@Orel2003, s.v. "*brandaz I"; @ClarkHall1960, s.v. "brand"; @BosworthToller1898, s.v. "brand"]. For this slice the contrast therefore has to stay explicit: regular oblique-cell comparator `*brándas -> brandes`, clearly attested lexeme/headword `brand`, and only indirect support in the checked sources for exact `brandes` as the row target.

DEV_NOTES preserves the row mainly as project-method chronology. The early paradigm-form note names `brand` among the items "successfully resolved by adopting a paradigm form in which the phonological development is lautgesetzlich" [DEV_NOTES:line-88-90]. A later weak-tail audit then states the general problem more bluntly: single proto-forms such as `*brandăz` cannot represent whole paradigms with alternations, because the transducer only derives one form per input [DEV_NOTES:line-1668-1674]. The ræst decision note makes the same point in row-specific comparative language when it says that using gen.sg. `*rastas -> ræstes` would be "parallel to hammer, swan, brand," and immediately warns that such encodings can misrepresent morphological class [DEV_NOTES:line-3216-3218]. Taken together, these are current method witnesses for describing `brandes` as an intentional paradigm-cell choice, not as the ordinary citation outcome and not as independent evidence that the noun itself underwent some special early analogical stem reshaping.

One mid-project fragment is worth keeping precisely because it is no longer the right primary explanation. In the no-metathesis control table, DEV_NOTES recorded `*brandaz -> *brandes* (gen.sg.)` while checking that a restricted `*st` metathesis rule did not overapply [DEV_NOTES:line-5024-5029]. That note is useful as replacement-note chronology because it shows the exact superseded detour: `brand` had already been drafted into an oblique-cell/testing role before the later cleanup. But because the fragment maps nominative input to genitive output, it should be cited only as diagnostic history, not as a philological source for exact `brandes` and not as the decisive rationale for the live row.

The later correction points the other way and should anchor any future write-up. In the `-ingaz` audit DEV_NOTES states that the plain nominative `*-az` ending is already fine and gives the specific witness `*brándaz -> brand` [DEV_NOTES:line-38129-38132]. That is the decisive contrast the slice has to preserve: regular lexeme-level comparator now available `*brándaz -> brand`; attested dictionary outcome `brand`; retained row target `brandes` only if the project deliberately keeps a separate gen.sg. cell. Any later report or row audit should therefore say explicitly that `brandes` is a preserved paradigm-cell choice from project chronology, not the only regular OE outcome now supported by the cascade.

## Superseded or diagnostic material

The important superseded material is the old assumption that `brand` needed an oblique workaround in order to behave regularly at all. The surviving DEV_NOTES history is still useful because it shows exactly how that workaround entered the project record and how it was later outflanked by `*brándaz -> brand`. What should not be blurred is the difference between "the project once used a genitive-style workaround" and "the lexeme can only be modeled through a genitive-style workaround."
