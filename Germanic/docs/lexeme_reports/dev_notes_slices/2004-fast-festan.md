## Development-note summary

This row only stays coherent if the three levels are kept separate. The live row keeps comparative `PROTO = *fastēną`, because Kroonen's headword is still the cognate-set baseline: `"Go. fastan, ON fasta, OE fastian, OFri. festia, OHG fastēn ww. 'to fast' < *fastēn-."` That comparative statement remains useful for the lexeme family and for the denominal connection to `*fastu- 'firm'`, but it is **not** the row's direct OE derivational input [@Kroonen2013, p. 131].

The OE-facing argument comes from the later DEV_NOTES rereading of Ringe and Taylor. Their formulation is preserved twice in the row history and remains the decisive handbook claim: OE fasting material belongs with `festan 'to fix, to fasten' < *fæstjan`, an `"originally class I weak verb"` that `"acquired the stative meaning ['to fast'] by lexical confusion"` with the `*fastēn-` family [@RingeTaylor2014, p. 101]. That is why the live row now uses `PROTOFORM = *fástijaną` and `COUNTERPART = festan`: the project no longer asks the cascade to derive OE directly from bare class-III `*fastēną`, whose regular project comparator was `faston`, nor does it keep the older target `fastian`.

The attested-OE side still needs careful wording rather than a flat one-form claim. DEV_NOTES' superseded mismatch phase initially treated `festan` as a failure because it expected `fæstan` or `fǣstan` after i-umlaut. The later correction explicitly reverses that reading: `æ` here is not the sound-law baseline but an analogical reshaping under the adjective `fæst`, so `festan` is the regular class-I project outcome while `fæstan`/`fǣstan` remain important analogical or lexicographic comparators [@RingeTaylor2014, p. 101; @BosworthToller1898, s.v. "festan"; @BosworthToller1898, s.v. "fæstan"]. Later report prose should therefore keep the contrast explicit: regular project comparator `*fastēną -> faston` for the abandoned class-III path, current row-target outcome `*fástijaną -> festan`, and analogically remodelled OE comparators `fæstan`/`fǣstan` that explain why the older bug diagnosis looked tempting.

One project detour must stay on the record because later writers would otherwise rediscover it. The long 2026-03-09 note first reframed row 2004 away from `fastian`, but then temporarily misread `*fastjăną -> festan` as an i-umlaut bug and recommended fixing the system toward `fæstan`. The subsequent `fastian resolution` note kept the class-I lexical-confusion account and the `festan` target, while rejecting the bug diagnosis and stating plainly that OE `æ` here is analogical. The live TSV then made one further cleanup beyond that resolution note: it restored `PROTO = *fastēną` as the comparative headword instead of keeping the note's temporary full-row switch to `*fastjăną`. That chronology matters because the current row depends on both moves at once: the class-I OE derivation was retained, but the comparative `PROTO` / row-specific `PROTOFORM` distinction was later reinstated.

## Superseded or diagnostic material

The main superseded material is the i-umlaut-bug phase, not the broader class-I reanalysis. In other words, the project was right to abandon `fastian` and the direct `*fastēną`-as-OE-input reading, but wrong to treat `festan` as an error that had to be repaired to `fæstan`. The current slice should therefore preserve two different historical warnings: `fastian` is a superseded target, and the later `fæstan-as-required-output` diagnosis is also superseded even though it was part of the path toward the correct class-I analysis.
