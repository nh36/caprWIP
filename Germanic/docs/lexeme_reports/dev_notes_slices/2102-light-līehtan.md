## Development-note summary

Row 2102 is a note-bearing but currently regular weak-verb row. The live FST already derives `*léuxtijaną -> līehtan`, so the working problem is not a sound-change failure or paradigm-cell rescue. The replacement note instead has to preserve normalization and lexeme-family boundaries: the row is the **verb** ‘to light, illuminate’, not the related noun `lēoht` and not the adjective `lēoht/leoht/liht` ‘light, not heavy’ [Germanic/data/germanic-aligned-final.tsv:666; Germanic/docs/lexeme_reports/packets/2102-light-līehtan.md:17-42, 99-109; Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:68-89].

The three levels still need to be kept distinct even though TSV `PROTO` and `PROTOFORM` happen to match. `PROTO = *léuxtijaną` is the comparative lexeme-level Germanic weak verb; `PROTOFORM = *léuxtijaną` is the project input form in the current PGmc `*-ij-` notation; and the OE target is normalized West-Saxon `līehtan`, not the related noun `lēoht` and not Anglian `lihtan` or later WS `lyhtan` [Germanic/data/germanic-aligned-final.tsv:666; Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:47-55, 57-66, 78-83]. The memo is explicit that the important contrast here is not PROTO-versus-PROTOFORM divergence but current PGmc input versus later OE dialectal outcomes [Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:49-55].

No securely attachable **current row-specific** DEV_NOTES argument survives beyond shared tables and audits. What survives as current authority is, first, DEV_NOTES' Fulk table quoting `"PGmc. *liuxtijanan > līehtan 'illuminate'"`, which supports the present `*-ij-` input and the verbal target, and second, the current `*xt` audit showing that row 2102 belongs among lexemes where `*x` before single `*t` is preserved rather than lost [Germanic/docs/DEV_NOTES.md:8961-8970, 39278-39288]. That is enough to support the row, but it is not the same thing as a dedicated lexeme-specific DEV_NOTES discussion. The slice therefore needs to say that plainly rather than implying a richer row-local DEV_NOTES authority than the repo actually contains [Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:15-20, 39-45, 68-83].

The superseded material also matters because packet excerpts can still blur old and current notation. DEV_NOTES line 8727 preserves an older pre-decision table in which `līehtan` appears beside `*leuxtjăną`; but the same DEV_NOTES range later marks that entire `-jăną` analysis as `SUPERSEDED` once the project adopted PGmc input notation and restored heavy-stem `*-ijăną`, with row 2102 specifically updated to `*leuxtijăną` [Germanic/docs/DEV_NOTES.md:8717-8759, 8763-8937]. The memo's warning is therefore correct: `*leuxtjăną` is checked project history only, not current row authority [Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:17-20, 72-76, 101-104].

OE philology belongs here only as controlled background. Ringe & Taylor give the verbal line `PGmce *liuhtijana ‘to shine, to illuminate’ ... > *liohtjan > WS *liehtjan > liehtan, Angl. *liohtjan > Merc. lihtan, North. lihta`, while Campbell and Brunner likewise distinguish WS `liehtan` from Anglian `lihtan` and Kentish `liohtan` [docs/references/ringe_taylor_linguistic_history_vol2.txt:14442-14448, 17753-17754; docs/references/campbell_old_english_grammar.txt:5878-5892; docs/references/brunner_1965_altenglische_grammatik.txt:24943-24945]. Those forms are useful comparator/background evidence for why the TSV counterpart is a normalized WS target, but they do not change the row's current selection of `līehtan` [Germanic/docs/analysis/ws_vs_anglian_dialect_differences.md:611-613, 637-642; Germanic/docs/lexeme_reports/research_memos/2102-light-līehtan.md:41-45, 57-66, 78-83].
