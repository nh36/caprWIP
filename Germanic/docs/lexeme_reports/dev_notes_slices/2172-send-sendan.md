## Development-note summary

No single long **row-dedicated** DEV_NOTES section survives for row 2172. The securely relevant material is instead distributed across shared sound-change and notation-policy fragments that name `sendan` or its proto spelling directly. Taken together, those fragments are still enough to replace a fresh DEV_NOTES search for this row. Their main current message is that OE `sendan` is **not** a live problem case: DEV_NOTES treats it as a regular heavy-stem class I weak verb whose `d` is already the correct voiced segment in the causative, and whose project proto/transponent spelling belongs in the `-ijaną` notation family rather than the older `-jăną` one [Germanic/docs/DEV_NOTES.md:7538-7570, 8972-9009; @RingeTaylor2014, pp. 157, 229].

The most row-specific linguistic point comes from the March 2026 systematic audit of `*nd` clusters. There DEV_NOTES explicitly lists `sendan | *sandjăną | causative of *sinþan- | Verner *d in causative | No (no *nþ cluster)` and then spells out the consequence: although the underlying strong verb has `þ`, the causative already contains the **voiced Verner alternant**, so the relevant cluster is `*-ndj-`, not `*-nþ-` or `*-nð-`; accordingly, nasal spirant law is irrelevant here [Germanic/docs/DEV_NOTES.md:7542-7564]. For row 2172 that means the live OE target should not be burdened with the `*d/*ð` representation problem that affects `funden`; `sendan` is cited in DEV_NOTES precisely as a counterexample to overgeneralizing that problem [Germanic/docs/DEV_NOTES.md:7564-7570; @Fulk2018, §3.6].

The second current point is not phonological but notational. DEV_NOTES preserves an earlier table where heavy-stem class I weak verbs, including `sendan`, were still being written with `-jăną`, i.e. `*sandjăną` [Germanic/docs/DEV_NOTES.md:8719-8739]. Later DEV_NOTES sections reverse that policy: one implementation/update table explicitly changes `*sandjăną` to `*sandijăną`, and the later analytical summary states as a criterion that a heavy-stem class I weak verb should have `-ijăną`, listing `*sandijăną` with stem `sand-` and weight `heavy` [Germanic/docs/DEV_NOTES.md:8911-8934, 8991-9009]. The direct Ringe-Taylor citation then gives the external anchor: `PGmc *sandijană 'to send'` [Germanic/docs/DEV_NOTES.md:8972-8987; @RingeTaylor2014, p. 229]. The live row's `PROTO = PROTOFORM = *sándijaną` should therefore be read as the current project transponent in the same notational camp as DEV_NOTES `*sandijăną`, not as a rival reconstruction.

For later review, the row needs one distinction kept explicit every time: the live table's `PROTO` and `PROTOFORM` are both `*sándijaną`, while DEV_NOTES discusses the same lexeme under multiple orthographic conventions (`*sandjăną`, `*sandijăną`, and R/T `*sandijană`). Those are notation-level variants in project discussion, not evidence for multiple OE targets. The OE target for row 2172 remains `sendan`, and none of the securely relevant DEV_NOTES material suggests a wrong-lexeme diagnosis, an irregular analogical rescue, or an unresolved `oe_known_problems.tsv` exception [Germanic/data/germanic-aligned-final.tsv:939-939; Germanic/docs/DEV_NOTES.md:7538-7570, 8972-9009].
