# Scaling plan for Old English lexeme-entry drafting

## Principle

Do **not** generate all 136 missing entries at once. The accepted shoulder model
should be treated as a genre benchmark, then tested on one more entry before any
larger batch.

## Immediate next test entry

Apply this writing skill to **`1980 cow / cȳ`** next.

Why this row:

- it is a `late_analogy` case, so it tests whether the skill transfers beyond
  shoulder;
- it is probably less complex than shoulder;
- the production backlog already identifies it as a strong model-entry
  candidate with manageable scope.

## After that: 3-entry mini-pilot

Before attempting the full 10-entry pilot batch, do a **3-entry mini-pilot**:

1. one `late_analogy`;
2. one `early_analogy`;
3. one `regular` with `NOTE`.

Each entry in the mini-pilot should include:

1. a source ledger;
2. a model/pilot entry;
3. an implementation report;
4. a reviewer-checklist result.

Only after those three are reviewed should the project move to the full
10-entry pilot batch.

## Recommended rollout sequence

1. `1980 cow / cȳ` as the next single-entry test.
2. Add one `early_analogy` entry.
3. Add one `regular`-with-`NOTE` entry.
4. Review all three for genre consistency.
5. Then begin the 10-entry pilot batch proposed in `production_backlog.md`.

## Scaling by class

### `late_analogy`

- Usually needs a `Paradigm comparison`.
- Must explain why the selected input differs from the citation form or default
  comparison form.
- Must compare the winning cell with an established OE paradigm form.

### `early_analogy`

- Needs a clear explanation of why the selected input differs from the citation
  form.
- Should explain the earlier stem, class, or branch-stage choice without
  reopening phonology wholesale.

### `regular` with `NOTE`

- Should be shorter.
- Should not be inflated just because there is abundant packet material.
- Keep the focus on the essential evidence and any non-obvious philological
  issue.

### `attested_variant`

- Needs careful Old English philology.
- Must distinguish default headword, attested variant, normalized spelling, and
  project-selected target.

### `reconstructed_oe`

- Must say explicitly that the OE target is reconstructed.
- Should explain why the reconstructed target is still useful to the project.

### `unexplained_unmodelled`

- Must state the limit of explanation clearly.
- Should not invent a paradigm escape route or speculative fix.

## Source-material discipline

- Existing source material should be used aggressively.
- Existing source material should **not** be narrated in the final entry.
- Packets, dev-note slices, memos, and dossiers are drafting inputs, not book
  prose.

## Manifest discipline

The manifest should **not** be updated until Nathan has accepted the prose style
for the new entries. Draft first, review second, promote later.
